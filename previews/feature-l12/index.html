ПАТЕРНИ ASYNC ОПЕРАЦІЙ

Три стани: loading / success / error

const initialState = {
  users: [],
  loading: false,
  error: null
};

const usersReducer = (state = initialState, action) => {
  switch (action.type) {
    case 'FETCH_USERS_REQUEST':
      return { ...state, loading: true, error: null };
    case 'FETCH_USERS_SUCCESS':
      return { ...state, loading: false, users: action.payload };
    case 'FETCH_USERS_FAILURE':
      return { ...state, loading: false, error: action.payload };
    default:
      return state;
  }
};

ASYNC ACTION CREATOR

export const fetchUsers = () => {
  return async (dispatch) => {
    try {
      dispatch({ type: 'FETCH_USERS_REQUEST' });

      const response = await fetch(
        'https://jsonplaceholder.typicode.com/users'
      );
      const data = await response.json();

      dispatch({
        type: 'FETCH_USERS_SUCCESS',
        payload: data
      });
    } catch (error) {
      dispatch({
        type: 'FETCH_USERS_FAILURE',
        payload: error.message
      });
    }
  };
};

  3 константи         FETCH_REQUEST / SUCCESS / FAILURE
  3 action creators
  3 case у reducer    + ручний spread стану
  1 thunk             try / catch / dispatch × 3
  store               createStore + applyMiddleware
                      + composeWithDevTools
  компонент           useEffect + dispatch + useSelector
  • Багато шаблонного коду
  • Легко помилитися з іммутабельністю
  • Кеш, повторні запити, скасування — вручну

REDUX SAGA

Для впізнавання в існуючих проєктах

function* fetchProducts(action) {
  try {
    const data = yield call(api.getProducts,
                            action.payload);
    yield put({ type: 'products/loaded',
                payload: data });
  } catch (e) {
    yield put({ type: 'products/failed',
                error: e.message });
  }
}

export function* rootSaga() {
  yield takeLatest('products/requested',
                   fetchProducts);
}
  • Middleware на генераторах (function*)
  • Декларативні ефекти: call, put, takeLatest
  • Була популярна у 2016–2020
  • Зараз: запити → RTK Query, реакція на дії → listener middleware

Трапляється в старих проєктах — варто впізнавати, але не обирати для нових

CREATESLICE: КОШИК

import { createSlice } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] },
  reducers: {
    added(state, action) {
      const item = state.items.find((i) => i.id === action.payload.id);
      if (item) item.qty += 1;
      else state.items.push({ ...action.payload, qty: 1 });
    },
    removed(state, action) {
      state.items = state.items.filter((i) => i.id !== action.payload);
    },
    cleared() {
      return { items: [] };
    },
  },
});

export const { added, removed, cleared } = cartSlice.actions;
export default cartSlice.reducer;

Порівняйте з cartReducer зі switch з лекції 10

IMMER: ПРАВИЛА

«Мутації», які насправді незмінні

// ✅ мутуємо чернетку
added(state, action) { state.items.push(action.payload); }

// ✅ повертаємо новий стан
cleared() { return { items: [] }; }

// ❌ і мутуємо, і повертаємо
removed(state, action) {
  state.count -= 1;
  return { ...state, items: [] };
}

// ❌ стрілка неявно повертає результат push
added: (state, action) => state.items.push(action.payload),
  • state — чернетка (Proxy). Immer будує новий незмінний обʼєкт
  • Або мутувати, або повертати — не обидва
  • console.log(state) показує Proxy → console.log(current(state))

CREATEASYNCTHUNK

Thunk з життєвим циклом

export const fetchProducts = createAsyncThunk(
  'products/fetch',
  async (category, { rejectWithValue, signal }) => {
    const res = await fetch(
      `https://dummyjson.com/products/category/${category}`, { signal });
    if (!res.ok) return rejectWithValue(`HTTP ${res.status}`);
    const data = await res.json();
    return data.products; // → action.payload у fulfilled
  },
  {
    // не запускати, якщо вже вантажиться
    condition: (category, { getState }) =>
      getState().products.status !== 'loading',
  },
);
  • Генерує три дії: products/fetch/pending, /fulfilled, /rejected
  • rejectWithValue — власний payload помилки
  • signal — скасування запиту

EXTRAREDUCERS

const productsSlice = createSlice({
  name: 'products',
  initialState: { items: [], status: 'idle', error: null },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchProducts.pending, (state) => {
        state.status = 'loading';
        state.error = null;
      })
      .addCase(fetchProducts.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.items = action.payload;
      })
      .addCase(fetchProducts.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.payload ?? action.error.message;
      });
  },
});
  • reducers — власні дії slice
  • extraReducers — реакція на чужі дії: thunks, інші slices
  • addMatcher — на групу дій, наприклад усі rejected

ТЕГИ: ІНВАЛІДАЦІЯ КЕШУ

getProducts: build.query({
  query: (category) => `/products/category/${category}`,
  transformResponse: (res) => res.products,
  providesTags: (products = []) => [
    ...products.map(({ id }) => ({ type: 'Product', id })),
    { type: 'Product', id: 'LIST' },
  ],
}),
updateProduct: build.mutation({
  query: ({ id, ...patch }) => ({ url: `/products/${id}`, method: 'PATCH', body: patch }),
  invalidatesTags: (result, error, { id }) => [{ type: 'Product', id }],
}),
addProduct: build.mutation({
  query: (body) => ({ url: '/products/add', method: 'POST', body }),
  invalidatesTags: [{ type: 'Product', id: 'LIST' }],
}),
  • Query надає теги, mutation їх інвалідує
  • RTK Query сам перезапитує всі query з інвалідованими тегами

ТЕГИ: ЯК ЦЕ ПРАЦЮЄ

getProducts('laptops')   → надає  [Product:1, Product:2, Product:LIST]
getProduct(2)            → надає  [Product:2]

updateProduct({ id: 2 }) → інвалідує [Product:2]
                              │
                              ▼
          перезапит getProducts('laptops') і getProduct(2)

addProduct({...})        → інвалідує [Product:LIST]
                              │
                              ▼
          перезапит лише списків

Описуємо залежності, а не «що перезапитати після чого»

ОПТИМІСТИЧНЕ ОНОВЛЕННЯ

updateProduct: build.mutation({
  query: ({ id, ...patch }) => ({ url: `/products/${id}`, method: 'PATCH', body: patch }),
  async onQueryStarted({ id, ...patch }, { dispatch, queryFulfilled }) {
    // 1. одразу змінюємо кеш
    const patchResult = dispatch(
      api.util.updateQueryData('getProduct', id, (draft) => {
        Object.assign(draft, patch);
      }),
    );
    try {
      await queryFulfilled; // 2. чекаємо на сервер
    } catch {
      patchResult.undo();   // 3. помилка → відкат
    }
  },
}),
  • Інтерфейс оновлюється миттєво, не чекаючи сервера
  • Та сама ідея, що й useOptimistic з лекції 5

ZUSTAND: STORE КОШИКА

// stores/cartStore.js
import { create } from 'zustand';

export const useCartStore = create((set, get) => ({
  items: [],

  add: (product) =>
    set((state) => {
      const item = state.items.find((i) => i.id === product.id);
      return {
        items: item
          ? state.items.map((i) => (i.id === product.id ? { ...i, qty: i.qty + 1 } : i))
          : [...state.items, { ...product, qty: 1 }],
      };
    }),

  remove: (id) => set((state) => ({ items: state.items.filter((i) => i.id !== id) })),
  clear: () => set({ items: [] }),
  total: () => get().items.reduce((sum, i) => sum + i.price * i.qty, 0),
}));
  • set зливає (merge) верхній рівень стану
  • get читає поточний стан усередині дій

ZUSTAND: СЕЛЕКТОРИ

// ✅ підписка на одне значення
const count = useCartStore((s) => s.items.length);
const add = useCartStore((s) => s.add);

// ❌ без селектора — ререндер на БУДЬ-ЯКУ зміну store
const { items, add } = useCartStore();

// ❌ новий обʼєкт на кожен виклик (у v5 — нескінченний цикл ререндерів)
const { items, clear } = useCartStore((s) => ({ items: s.items, clear: s.clear }));

// ✅ useShallow порівнює поля обʼєкта
import { useShallow } from 'zustand/react/shallow';
const { items, clear } = useCartStore(
  useShallow((s) => ({ items: s.items, clear: s.clear })),
);

Те саме правило, що й у useSelector: селектор має повертати стабільне значення

ZUSTAND: MIDDLEWARE

import { create } from 'zustand';
import { persist, devtools } from 'zustand/middleware';
import { immer } from 'zustand/middleware/immer';

export const useCartStore = create(
  devtools(
    persist(
      immer((set) => ({
        items: [],
        add: (product) => set((state) => {
          const item = state.items.find((i) => i.id === product.id);
          if (item) item.qty += 1; // Immer: мутуємо, як у createSlice
          else state.items.push({ ...product, qty: 1 });
        }),
      })),
      { name: 'cart' }, // ключ у localStorage
    ),
  ),
);

ПОШИРЕНІ ПОМИЛКИ

  • Мутувати стан поза createSlice / Immer
  • Зберігати серверні дані в slice замість RTK Query
  • Селектор повертає новий масив чи обʼєкт без createSelector / useShallow
  • Усе в глобальному store: поля форм, відкриті модалки
  • Несеріалізовані значення в store: класи, Promise, функції
  • Zustand без селектора — ререндер на кожну зміну
