USEEFFECT

  • Можливість виконання сторонніх дій (ефектів)
  • componentDidMount + componentDidUpdate + componentWillUnmount
  • Що компонент має зробити після рендера
  • useEffect не блокує рендеринг

USEEFFECT

Синтаксис

useEffect(effect, [deps]);

USEEFFECT

useEffect(() => {
  console.log(`useEffect. Execute every time`);
});

USEEFFECT

componentDidMount

useEffect(() => {
  console.log(`useEffect. Render once on onload`);
}, []);

USEEFFECT

componentWillUnmount

useEffect(() => {
  console.log(`useEffect. Render once on onload`);
  return (() => console.log(`useEffect. Render once on unload`));

USEEFFECT

componentDidUpdate

  fetch(`https://jsonplaceholder.typicode.com/${type}/1`)

USEEFFECT

Залежності (Dependencies)

  • [] (порожній масив) - виконується один раз при mount
  • [value] - виконується при зміні value
  • без масиву - виконується при кожному render
  • [a, b, c] - виконується при зміні будь-якого з a, b, c

USEEFFECT

Правила залежностей

function MyComponent() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('');

  // ❌ Відсутні залежності
  useEffect(() => {
    console.log(`Count is ${count}`);
  }); // Буде виконуватися при кожному рендері

  // ✅ Правильні залежності
  useEffect(() => {
    console.log(`Count is ${count}`);
  }, [count]); // Тільки при зміні count
}

USEEFFECT

Коли ефект НЕ потрібен

  • Похідні дані рахуй під час рендера, а не в ефекті
  • Не дублюй props у стан через useEffect
  • Трансформацію для відображення роби прямо в рендері
  • Ефект — лише для роботи із зовнішнім світом: мережа, DOM, підписки, таймери

USEEFFECT

Похідний стан — без ефекту

// ❌ зайвий ефект + зайвий стан + зайвий ре-рендер
const [fullName, setFullName] = useState('');
useEffect(() => {
  setFullName(first + ' ' + last);
}, [first, last]);

// ✅ просто порахувати при рендері
const fullName = first + ' ' + last;

Найчастіша помилка — класти в useEffect те, що не є справжнім side effect

USEEFFECT

Хуки — це патерн, а не синтаксис

  • useEffect — найчастіше неправильно вживаний хук
  • Не роби з нього «універсальний інструмент» на всі випадки
  • Розділяй логіку від UI → більшість логіки тестується без рендера
  • React рухається до data-driven: Server Components, use(), серверні дії

USEEFFECTEVENT

Свіжі значення без роздування залежностей

function Chat({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showToast('Connected!', theme); // завжди свіжий theme
  });

  useEffect(() => {
    const conn = connect(roomId);

«Бачить» останні props/state, але сам не перезапускає ефект. Поки експериментальний.

USEMEMO

Мемоїзація - це метод оптимізації, який в основному використовується для прискорення комп'ютерних програм шляхом зберігання результатів дорогих викликів функцій та повернення кешованого результату, коли виклики на однакових вхідних даних відбуваються знову.

  • Кешування об'єктів
  • Кешування важких функцій

USEMEMO

Синтаксис

const memoValue = useMemo(() => {
  expensiveOperationHere(data, value)
}, [data, value]);

function counterReducer(state, action) {
  switch (action.type) {
    case 'INCREMENT':
      return {count: state.count + 1};
    case 'DECREMENT':
      return {count: state.count - 1};
    default:
      return state;
  }
}

ВЛАСНІ ХУКИ

  • Функції що починаються з "use"
  • Повторне використання логіки між компонентами
  • Можуть використовувати інші хуки
  • Слідують правилам хуків
  • Інкапсулюють доменну логіку, відділяючи її від UI
  • Логіку можна тестувати без рендера компонентів

useLocalStorage приклад

import {useState, useEffect} from "react";

function useLocalStorage(key, initialValue) {
  const [storedValue, setStoredValue] = useState(() => {
    try {
      const item = window.localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch (error) {
      return initialValue;
    }
  });

  const setValue = (value) => {
    try {
      setStoredValue(value);
      window.localStorage.setItem(key, JSON.stringify(value));
    } catch (error) {
      console.log(error);
    }
  };

  return [storedValue, setValue];
}

// Використання

USEIMPERATIVEHANDLE

Кастомний API для батьківського ref

function TextInput({ ref }) {          // React 19: ref як звичайний проп
  const inputRef = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    clear: () => { inputRef.current.value = ''; },
  }));
  return <input ref={inputRef} />;
}
// батько бачить лише focus() і clear(), а не весь DOM-вузол

USESYNCEXTERNALSTORE

  • Підписка на зовнішнє сховище чи браузерні API
  • Синхронні оновлення без «розривів» (tearing)
  • Основа для Redux, Zustand та інших сторів
function useOnlineStatus() {
  return useSyncExternalStore(
    (cb) => {                       // subscribe
      window.addEventListener('online', cb);
      return () => window.removeEventListener('online', cb);
    },
    () => navigator.onLine,         // snapshot на клієнті
    () => true                      // snapshot на сервері
  );
}

ПОВНИЙ ПЕРЕЛІК ХУКІВ

React 19

  • Стан: useState, useReducer
  • Контекст: useContext
  • Рефи: useRef, useImperativeHandle
  • Ефекти: useEffect, useLayoutEffect, useInsertionEffect
  • Продуктивність: useMemo, useCallback, useTransition, useDeferredValue
  • Інше: useId, useSyncExternalStore, useDebugValue

ОПТИМІЗАЦІЯ ПРОДУКТИВНОСТІ

  • React.memo() - мемоїзація компонентів
  • useMemo() - кешування обчислень
  • useCallback() - кешування функцій
  • React.lazy() + Suspense - код-сплітінг

BEST PRACTICES

  • Виносьте логіку в custom hooks
  • Слідкуйте за залежностями useEffect
  • Не зловживайте useMemo/useCallback
  • Розділяйте state по логічних групах
  • Похідний стан — у рендері, ефекти лише для side effects
  • Композиція з малих, вузькоспеціалізованих хуків
