КОЛИ ВИКОРИСТОВУВАТИ REDUX?

✓ Варто використовувати

  • Складна логіка стану
  • Багато компонентів використовують один стан
  • Потреба в передбачуваності
  • Часті оновлення стану
  • Велика команда розробників
  • Потреба в time-travel debugging

✗ НЕ варто використовувати

  • Малий проєкт (до 10 компонентів)
  • Простий локальний стан
  • Стан використовується в 1-2 компонентах
  • Прототипування/MVP
  • Статичні дані

REDUX

  • Автор – Ден Абрамов
  • Бібліотека для організації архітектури застосунку
  • Однонаправлений потік даних
  • Іммутабельний стан

FLUX АРХІТЕКТУРА

REDUX

STATE. СТАН.

Місце, де зберігається весь стан застосунку.

ACTION. ДІЯ.

  • Стан неможливо змінювати напряму
  • Стан необхідно змінювати через дію
  • Те, "як" ми змінюємо дані

DISPATCH. ДІСПЕТЧЕР.

  • Звертаємось до діспетчера
  • Передаємо дію
  • Той, "хто" ми змінюємо дані

REDUCER. РЕДЮСЕР.

  • Система, через яку проходить взаємодія
  • Знаходиться вся логіка
  • Там, "де" працюють з даними

STORE

createStore і Provider

import { createStore } from 'redux';
import { Provider } from 'react-redux';

const defaultState = {
  counter: 0
}

const counterReducer = (state = defaultState, action) => {
  switch (action.type) {
    case "INCREASE_COUNTER":
      return {...state, counter: state.counter + Number(action.payload)};
    case "DECREASE_COUNTER":
      return {...state, counter: state.counter - Number(action.payload)};
    default:
      return state;
  }
}

const store = createStore(counterReducer);

root.render(
  <React.StrictMode>
    <Provider store={store}>
      <App />
    </Provider>
  </React.StrictMode>
);

BEST PRACTICES

  • Нормалізація даних - зберігайте дані в плоскому вигляді, як в БД
  • Використовуйте селектори - створюйте функції для вибірки даних
  • Мемоізація - використовуйте reselect для оптимізації
  • Не зберігайте все в Redux - локальний UI стан залишайте в компонентах
  • Іменування actions - використовуйте формат "domain/eventName"
  • Redux Toolkit - використовуйте RTK замість plain Redux

MIDDLEWARE

Проміжний шар між dispatch і reducer

  • Перехоплює actions перед тим, як вони потраплять до reducer
  • Може змінювати, затримувати, або блокувати actions
  • Використовується для async логіки, логування, аналітики
  • Middleware викликаються в ланцюжку

const loggerMiddleware = (store) => (next) => (action) => {
  console.log('Dispatching:', action);
  console.log('State before:', store.getState());

  const result = next(action);

  console.log('State after:', store.getState());
  return result;
};

ПАТЕРНИ ASYNC ОПЕРАЦІЙ

Три стани: loading / success / error

const initialState = {
  users: [],
  loading: false,
  error: null
};

const usersReducer = (state = initialState, action) => {
  switch (action.type) {
    case 'FETCH_USERS_REQUEST':
      return { ...state, loading: true, error: null };
    case 'FETCH_USERS_SUCCESS':
      return { ...state, loading: false, users: action.payload };
    case 'FETCH_USERS_FAILURE':
      return { ...state, loading: false, error: action.payload };
    default:
      return state;
  }
};

ASYNC ACTION CREATOR

export const fetchUsers = () => {
  return async (dispatch) => {
    try {
      dispatch({ type: 'FETCH_USERS_REQUEST' });

      const response = await fetch(
        'https://jsonplaceholder.typicode.com/users'
      );
      const data = await response.json();

      dispatch({
        type: 'FETCH_USERS_SUCCESS',
        payload: data
      });
    } catch (error) {
      dispatch({
        type: 'FETCH_USERS_FAILURE',
        payload: error.message
      });
    }
  };
};

REDUX SAGA

npm i redux-saga
  • Потужне middleware для складної async логіки
  • Побудоване на генераторах ES6
  • Декларативний підхід до side effects
  • Легко тестувати
  • Підтримка складних сценаріїв (cancel, debounce, race)

REDUX SAGA: EFFECTS

Основні ефекти для роботи з async операціями

  • call - викликає функцію (async або sync)
  • put - dispatch action
  • takeEvery - слухає кожну action
  • takeLatest - слухає тільки останню action (скасовує попередні)
  • select - отримує дані зі state
  • fork - запускає паралельну задачу
  • cancel - скасовує задачу

REDUX SAGA: ПРИКЛАД

import { call, put, takeEvery } from 'redux-saga/effects';

// Worker saga
function* fetchUsersSaga() {
  try {
    yield put({ type: 'FETCH_USERS_REQUEST' });

    const response = yield call(fetch,
      'https://jsonplaceholder.typicode.com/users'
    );
    const users = yield call([response, 'json']);

    yield put({ type: 'FETCH_USERS_SUCCESS', payload: users });
  } catch (error) {
    yield put({ type: 'FETCH_USERS_FAILURE', payload: error.message });
  }
}

// Watcher saga
function* watchFetchUsers() {
  yield takeEvery('FETCH_USERS', fetchUsersSaga);
}

export default watchFetchUsers;

REDUX SAGA: КОНФІГУРАЦІЯ

import { createStore, applyMiddleware } from 'redux';
import createSagaMiddleware from 'redux-saga';
import rootReducer from './reducers';
import watchFetchUsers from './sagas/usersSaga';

const sagaMiddleware = createSagaMiddleware();

const store = createStore(
  rootReducer,
  applyMiddleware(sagaMiddleware)
);

sagaMiddleware.run(watchFetchUsers);

export default store;

Redux Toolkit - офіційно рекомендований спосіб використання Redux

IMMER - "МУТАЦІЇ"

RTK використовує Immer для спрощення роботи зі станом

Без Immer (Plain Redux)

case 'ADD_TODO':
  return {
    ...state,
    todos: [
      ...state.todos,
      action.payload
    ]
  };

З Immer (RTK)

addTodo: (state, action) => {
  state.todos.push(action.payload);
}

Immer автоматично створює новий іммутабельний стан

CREATEASYNCTHUNK

import { createAsyncThunk, createSlice } from '@reduxjs/toolkit';

export const fetchUsers = createAsyncThunk(
  'users/fetchUsers',
  async () => {
    const response = await fetch(
      'https://jsonplaceholder.typicode.com/users'
    );
    return response.json();
  }
);

const usersSlice = createSlice({
  name: 'users',
  initialState: { users: [], status: 'idle' },
  extraReducers: (builder) => {
    builder
      .addCase(fetchUsers.pending, (state) => {
        state.status = 'loading';
      })
      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.users = action.payload;
      })
  }
});

RTK QUERY: СТВОРЕННЯ API

import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

export const usersApi = createApi({
  reducerPath: 'usersApi',
  baseQuery: fetchBaseQuery({
    baseUrl: 'https://jsonplaceholder.typicode.com'
  }),
  endpoints: (builder) => ({
    getUsers: builder.query({
      query: () => '/users',
    }),
    getUserById: builder.query({
      query: (id) => `/users/${id}`,
    }),
    addUser: builder.mutation({
      query: (newUser) => ({
        url: '/users',
        method: 'POST',
        body: newUser,
      }),
    }),
  }),
});

export const { useGetUsersQuery, useGetUserByIdQuery, useAddUserMutation } = usersApi;

RTK QUERY: КОНФІГУРАЦІЯ STORE

import { configureStore } from '@reduxjs/toolkit';
import { usersApi } from './services/usersApi';

export const store = configureStore({
  reducer: {
    [usersApi.reducerPath]: usersApi.reducer,
  },
  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(usersApi.middleware),
});

import { useGetUsersQuery, useAddUserMutation } from './services/usersApi';

      </button>
      <ul>
        {users?.map(user => <li key={user.id}>{user.name}</li>)}
      </ul>
    </div>
  );
};

ПОШИРЕНІ ПОМИЛКИ

  • Мутація стану напряму - завжди повертайте новий об'єкт (або використовуйте RTK)
  • Занадто багато даних в store - не зберігайте форми, UI стан
  • Відсутність нормалізації - вкладені дані ускладнюють оновлення
  • Великі редюсери - розбивайте на менші з combineReducers
  • Синхронна логіка в reducers - використовуйте middleware для async
  • Прямий dispatch без action creators - створюйте функції для дій
